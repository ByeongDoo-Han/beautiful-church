# 아름다운교회 영아부 · 예배 운영 MVP

## 운영 배포 원칙

변경사항 검증 → `main` 커밋·푸시 → 해당 커밋의 CI 성공 확인 → `npm run deploy:main` 순서로 진행합니다. 이 명령은 현재 커밋과 원격 `main`이 같고 앱 소스에 미커밋 변경이 없는지 검사한 뒤, 별도의 깨끗한 체크아웃에서 배포합니다. 작업 파일을 임시 폴더에 복사해서 직접 배포하지 않습니다.

운영 인증 스모크 검증은 비공개 환경에 `WORSHIP_TEST_PASSWORD`를 설정한 뒤 실행합니다. `.env.local`을 사용할 때는 `node --env-file=.env.local scripts/test-login-required.mjs`처럼 실행합니다. CI는 운영 계정과 다른 테스트 비밀번호를 사용합니다. `artifacts/`의 운영 스크린샷은 로컬 검증 자료이며 공개 저장소에 추가하지 않습니다.

Next.js + TypeScript 기반의 실행 가능한 예배 콘솔입니다. 기존 Vercel Hobby 설계를 바탕으로 실제 브라우저 렌더링, 운영자 콘솔, 출력창 동기화와 오프라인 동작을 구현했습니다.

## 빠른 실행

```sh
git clone https://github.com/ByeongDoo-Han/beautiful-church.git
cd beautiful-church
```

Node.js 22.13 이상을 사용합니다. 의존성 버전은 `package-lock.json`에 고정되어 있습니다.

```sh
npm ci
npm run dev
```

브라우저에서 [운영자 콘솔](http://127.0.0.1:3000/admin)을 엽니다. `SESSION_SECRET`을 설정하고 로그인해야 사용할 수 있습니다. Blob 환경변수가 없으면 로그인 후 샘플 자료로 시작합니다. 샘플 PPTX 3장, PDF 3쪽, 직접 생성한 18초 테스트 음원이 포함되어 있습니다. 실제 찬양 음원은 사용자가 불러옵니다.

오프라인까지 시험할 때는 개발 서버 대신 아래 명령을 사용합니다.

```sh
npm run build
npm start -- --port 3100
```

[프로덕션 모드 콘솔](http://127.0.0.1:3100/admin)에서 **예배 자료 다운로드**를 누르고 저장 위치를 선택한 뒤 완료 안내를 확인하세요. 그다음 로그인한 운영·출력 화면을 유지한 채 인터넷을 끊어 검증할 수 있습니다. 새 창 및 새로고침에는 온라인 로그인 확인이 필요합니다. `npm run build`는 PDF.js Worker/폰트/CMap/WASM과 Next.js 정적 파일의 캐시 목록도 생성합니다.

## 예배 진행

1. **예배 순서 · 자료 편집**에서 PPTX, PDF, MP3를 불러옵니다. 파일은 SHA-256 ID로 이 PC의 IndexedDB에 저장됩니다. 같은 파일은 재사용합니다.
2. 각 순서에 MP3, 프레젠테이션, 필요하면 대체 PDF를 연결합니다. 제목과 순서를 수정할 수 있습니다. 곡 선택 시 이전 곡은 정지하며 다음 곡을 자동 재생하지 않습니다.
3. **예배 자료 다운로드**를 누르면 지원 브라우저에서 ZIP 파일의 저장 위치와 이름을 선택합니다. 원본 MP3/PPTX/PDF와 예배 순서·슬라이드 편집 정보(`예배정보.json`)를 함께 보관하며, 편집 문구는 원본 PPTX에 반영되지 않습니다. ZIP은 자료 보관용으로 전체 편집본 재가져오기는 지원하지 않습니다. 위치 선택 미지원 브라우저는 일반 다운로드 설정을 따릅니다. 기존 앱 내부 오프라인 준비도 함께 실행하므로 로그인한 운영·출력 화면을 유지하면 자료를 오프라인에서도 사용할 수 있습니다. 새로 열거나 새로고침할 때는 온라인 로그인 확인이 필요합니다.
4. 지원 브라우저에서는 **두 번째 화면 자동 선택**을 눌러 화면 접근 권한을 허용합니다. 현재 운영자 화면과 다른 외부 화면을 우선 선택하며, 직접 화면을 선택할 수도 있습니다.
5. **출력창 열기**를 누릅니다. 선택한 화면이 있으면 해당 좌표에 배치를 요청합니다. 미지원·권한 거절·단일 화면이면 출력창을 직접 이동합니다. 팝업 차단 시 허용 후 같은 버튼을 다시 누릅니다.
6. 출력창의 **전체화면 시작** 또는 콘솔의 **전체화면 요청**을 누릅니다. 거절되면 출력창에서 직접 클릭합니다. 전체화면 중에는 슬라이드만 보이고 제어 안내가 사라집니다.
7. 콘솔에서 이전/다음, 현재/다음 미리보기, 화면 가리기, 전체화면 해제·창 닫기, 음원 재생/일시정지/볼륨/탐색을 제어합니다. 음원은 운영자 PC의 기본 오디오 출력 장치로 나갑니다.

단축키: 콘솔 `←` / `→` / `Space` 슬라이드 이동, `B` 화면 가리기. 출력창 `←` / `→` / `Space` 이동, `F` 전체화면, `Esc` 전체화면 해제 및 안내 표시, 더블클릭 안내 토글. 입력창과 볼륨/진행바에서는 해당 입력의 기본 키보드 동작을 유지합니다.

관리자 로그인 후 왼쪽의 **서버 파일 목록**에서 실제 Vercel Blob 저장 파일의 이름·종류·용량·업로드 일시와 예배 목록 등록 여부를 확인할 수 있습니다. **새로고침**으로 다시 조회하고 파일이 많으면 **파일 더 불러오기**로 이어서 확인합니다. 예배 순서 설정 파일(`data/manifest.json`)은 제외하며, 예배 목록에 없는 파일은 Blob에 저장된 이름으로 표시합니다. 목록 조회는 온라인에서 가능합니다.

## 유튜브 찬양과 가사 화면 분리

1. **예배 순서 · 자료 편집**에서 카드의 **찬양 재생 방식**을 **유튜브 링크 · 화면 1**로 선택합니다.
2. 유튜브 영상 링크를 붙여 넣고 **링크 적용**을 누릅니다. 링크의 `t=90`, `t=1m30s`, `start=90` 시작 위치를 저장합니다.
3. 같은 카드의 **프레젠테이션**에 가사 PPTX 또는 PDF를 연결합니다. 유튜브에서 가사를 자동 추출하지 않습니다.
4. 편집을 닫고 화면 1의 유튜브 플레이어에서 재생·일시정지·음량을 조절합니다. 화면 2에는 연결한 슬라이드만 표시되며 유튜브 플레이어나 별도 음원 재생기는 생성되지 않습니다.
5. 카드 변경 시 이전 플레이어를 정리합니다. MP3/유튜브는 한 번에 하나만 표시·재생합니다. 편집창으로 가리거나 플레이어가 화면 밖으로 벗어나거나 운영자 탭이 숨겨지면 유튜브 재생을 일시정지합니다.

유튜브는 인터넷 연결이 필요하며 **예배 자료 다운로드**에 영상·음원이 포함되지 않습니다. 기존 MP3 연결은 유지되어 재생 방식을 MP3로 바꾸면 사용할 수 있습니다. 링크 설정은 다른 카드 편집과 동일하게 현재 브라우저에 자동 저장되고, **서버 저장**을 누르면 서버 예배 목록에도 저장됩니다. 유튜브 iframe에만 `strict-origin-when-cross-origin`을 지정해 사이트 식별에 필요한 Referer를 전달하며 다른 페이지의 기본 보안 헤더는 유지합니다.

## 브라우저 제약

- **임의의 두 번째 모니터에 강제로 전체화면을 띄우는 보장은 없습니다.** 화면 탐색과 배치는 권한, 브라우저 지원, OS 창 정책에 영향을 받습니다. 화면 복제 모드에서는 두 모니터가 독립 화면으로 보이지 않을 수 있습니다.
- Window Management는 HTTPS/localhost에서 기능을 감지합니다. `getScreenDetails()` 권한 요청과 `window.open()`을 별도 클릭으로 나누어 권한 응답을 기다리다가 팝업 사용자 활성화를 잃지 않도록 했습니다.
- `requestFullscreen({ screen })`을 사용할 수 있으면 선택 화면을 전달합니다. 일반 요청은 현재 출력창의 화면을 사용합니다. 요청 성공 여부는 Promise와 실제 `fullscreenchange`로 판단합니다.
- BroadcastChannel/postMessage는 사용자 클릭 권한을 만들지 않습니다. 콘솔의 직접 요청 또는 메시지 요청이 거절되면 출력창 자체에서 클릭하도록 안내합니다. 요청만 했다고 전체화면 성공으로 표시하지 않습니다.
- **운영 콘솔 한 개와 해당 출력창 한 개**가 기본 사용 단위입니다. 다른 기기 간 원격 제어, 브라우저 프로필 간 통신은 포함하지 않습니다. 탭 복제는 세션 저장소까지 복제할 수 있으므로 콘솔을 동시에 복제해 운영하지 마세요.
- PPTX는 PowerPoint의 모든 기능을 재현하지 않습니다. 애니메이션, 일부 도형/미디어/폰트는 다르게 보일 수 있습니다. 예배 전 실제 파일로 리허설하고, 필요하면 PowerPoint에서 내보낸 PDF를 연결해 **PDF로 전환**합니다. PDF.js는 사용자가 제공한 PDF를 렌더링하며 PPTX를 자동으로 PDF로 바꾸지 않습니다.
- 샘플 PDF는 독립적으로 만든 영문 테스트 자료입니다. 샘플 PPTX를 정확하게 변환한 PDF라고 가정하지 마세요.

## Vercel 연결

1. GitHub의 `ByeongDoo-Han/beautiful-church` 저장소를 Vercel에 Import하고 Root Directory를 저장소 루트(`./`)로 설정합니다. Node.js 22 이상을 선택합니다. Build Command는 `npm run build`입니다.
2. **Private Blob store**를 생성하고 프로젝트에 연결합니다. 읽기/쓰기 토큰은 서버 전용 `BLOB_READ_WRITE_TOKEN`으로 설정합니다.
3. 예측 불가능한 32자 이상의 `SESSION_SECRET`을 설정합니다. 관리자 아이디는 `admin`이며 `npm run password`로 만든 scrypt 검증값을 `ADMIN_PASSWORD_HASH`에 설정합니다. 운영 비밀번호와 검증값은 저장소에 올리지 않습니다. 로컬 개발은 `.env.example`을 `.env.local`로 복사해 값을 채웁니다.
4. 배포 후 `/login`으로 로그인합니다. 자료를 불러와 편집하고 **서버 저장**을 누릅니다. 브라우저가 Blob에 직접 업로드하고, 완료된 파일 정보만 manifest API에 전송합니다. MP3/PPTX 파일 전체를 Vercel Function에 전송하지 않습니다.
5. 다른 PC에서도 로그인한 뒤 서버에 저장된 자료를 조회하고 **예배 자료 다운로드**를 실행할 수 있습니다. 관리자는 로그인 후 필요하면 **서버 자료 다시 불러오기**를 실행합니다. 저장 충돌 시 임의로 덮어쓰지 않고 서버 자료를 다시 읽도록 안내합니다. 다시 불러오기는 로컬 편집을 교체하므로 확인 UI가 있습니다.

서버 환경변수가 없으면 클라우드 API를 사용할 수 없습니다. 예배 화면과 출력 화면, 서버 예배 목록·파일 다운로드·업로드·서버 저장·Blob 파일 목록은 모두 관리자 인증이 필요합니다. 등록되지 않은 파일과 임의 경로의 서명 URL은 발급하지 않습니다. 세션 쿠키는 HttpOnly, SameSite=Strict, HTTPS에서 Secure, 12시간 만료입니다.

**Hobby 무료 한도 내 운용을 목표로 한 구조이며 무조건 월 0원을 보장하지 않습니다.** 계정의 Hobby 이용 조건과 현재 저장·전송·요청 한도는 Vercel 대시보드에서 확인하세요. 파일당 MP3 15MiB, PPTX/PDF 20MiB, 업로드 전 저장량 약 800MiB 보호 검사가 있습니다. 이 검사는 동시 업로드 예약을 원자적으로 합산하지 않으므로 엄격한 전체 용량 제한이나 과금 차단 장치가 아닙니다.

## 검증 명령

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 설치된 Google Chrome을 새 테스트 프로필로 실행하며 3100 포트를 사용합니다. 이미 사용 중이면 `PLAYWRIGHT_PORT=3197 npm run test:e2e`로 변경합니다. 일반 E2E 테스트는 실제 Blob에 접근하지 않습니다. Chrome이 없는 환경은 Playwright의 브라우저를 설치하고 `playwright.config.ts`의 `channel`을 환경에 맞게 변경합니다. fixtures 재생성은 `npm run fixtures`입니다. 배포용 런타임에는 샘플 생성 도구를 사용하지 않습니다.

오프라인 앱 목록은 `runAfterProductionCompile`에서 생성합니다. Vercel이 정적 파일을 수집하기 전에 현재 빌드의 파일 주소를 기록하여 이전 빌드의 청크가 배포 목록에 남지 않도록 합니다.

실제 Blob 왕복 테스트는 `.env.local`에 연결한 저장소와 세션 설정을 넣고 빌드 후 `node --env-file=.env.local scripts/test-blob.mjs`로 실행합니다. 빈 자료실에서만 실행하며 기존 예배 자료가 있으면 중단합니다. 브라우저에서 MP3/PPTX를 업로드하고, 새 브라우저 환경에서 다운로드한 파일의 크기·SHA-256과 오프라인 렌더·재생을 확인한 뒤 테스트 파일을 정리합니다. `BLOB_TEST_BASE_URL`을 지정하면 로컬 서버 대신 해당 배포를 테스트합니다. 이때 환경파일의 Blob 저장소와 배포의 저장소가 같아야 합니다.

## 운영 범위

- 실제 Vercel Private Blob(서울 리전) 연결과 브라우저 MP3/PPTX 업로드·다운로드, 파일 크기·SHA-256 일치 및 오프라인 재생을 검증했습니다. 실물 두 모니터/프로젝터 배치는 별도 리허설이 필요합니다.
- 아이디 `admin`을 사용하는 단일 관리자 MVP입니다. 비밀번호의 scrypt 검증값과 세션 서명 키는 서버 환경변수로 관리합니다. MFA·다중 계정·감사 로그·중앙 세션 폐기는 아직 없습니다.
- 오프라인 자료는 로그인 쿠키가 만료되어도 해당 PC에 남아 재생됩니다. 공유 PC에서는 출력창을 닫고 **이 PC 저장 자료 지우기**를 실행하세요. 이는 서버 파일을 삭제하지 않습니다. 브라우저 저장소 삭제/퇴거, 시크릿 모드, 처음 방문하는 PC에는 오프라인 자료가 없습니다.
- 순서에서 항목을 제거해도 원본 Blob은 삭제하지 않습니다. 원본 정리는 현재 Vercel 대시보드에서 수동으로 수행합니다. 자동 삭제/백업·보존 정책은 포함하지 않습니다.
- 서비스를 배포하거나 렌더러를 업데이트한 뒤에는 온라인에서 다시 **예배 자료 다운로드**를 완료하고 리허설하세요.

구현 시 확인한 1차 자료: [Vercel Client Upload](https://vercel.com/docs/vercel-blob/client-upload), [Signed URLs](https://vercel.com/docs/vercel-blob/vercel-signed-urls), [Blob SDK](https://vercel.com/docs/vercel-blob/using-blob-sdk), [Window Management](https://developer.chrome.com/docs/capabilities/web-apis/window-management), [PPTX renderer](https://github.com/aiden0z/pptx-renderer), [PDF.js](https://mozilla.github.io/pdf.js/examples/).

## 웹에서 PPT 문구와 슬라이드 편집

PPTX가 연결된 카드를 선택한 뒤 **슬라이드 편집**을 누릅니다. 문구를 바꾸거나 **슬라이드 복사·추가**로 현재 장의 디자인과 문구를 복사하고, **슬라이드 삭제**로 불필요한 장을 제거합니다. 최소 한 장을 유지하며 최대 1,000장까지 지원합니다. 편집창 미리보기를 확인한 뒤 **화면에 적용**을 누르면 현재 화면과 출력창이 함께 바뀝니다. 적용 전 수정과 취소는 화면 2에 반영되지 않습니다.

변경은 선택한 카드가 속한 PPT 섹션에 적용되며 이 PC에 자동 저장됩니다. 같은 파일을 쓰더라도 다른 섹션의 편집 내용은 독립적으로 유지됩니다. 관리자가 **서버 저장**을 누르면 편집 내용과 장 순서를 예배 설정에 저장하므로 기존 PPTX를 다시 업로드하지 않습니다. 다른 PC에서 서버 자료를 불러오면 동일하게 표시됩니다.

일반 텍스트 상자, 그룹 안의 텍스트와 표 셀을 지원합니다. 변경하지 않은 문단은 원래 서식을 유지하고 수정한 문단은 첫 글자의 서식을 사용합니다. 이미지 안의 글자, 차트·마스터 문구는 편집 대상이 아닙니다. 원본 PPTX 파일 자체와 대체 PDF는 변경하지 않으며 수정본 PPTX 다운로드는 제공하지 않습니다. 연결 PPTX를 다른 파일로 교체하면 해당 섹션의 웹 편집 내용을 초기화합니다.

## PPT 섹션과 예배 순서 카드

왼쪽 예배 순서 목록은 **PPT 파일 이름 → 그 아래 예배 순서 카드**로 구성됩니다. 같은 섹션의 카드는 같은 자료와 현재 페이지를 사용하고, 음원/유튜브는 카드별로 바뀝니다. 다른 섹션으로 전환하면 해당 섹션 자료의 첫 장을 표시합니다.

- 카드를 다른 PPT 섹션의 제목 또는 하단으로 끌면 그 섹션 마지막에 배치합니다. 다른 카드 위로 끌면 그 카드 앞에 배치합니다.
- 카드 옆 이동 아이콘을 클릭하면 섹션 선택과 위·아래 버튼을 사용할 수 있습니다. 터치 또는 키보드만으로도 배치할 수 있습니다.
- **PPT 섹션 추가**에서 등록한 PPT/PDF를 선택해 빈 섹션을 만들고, 섹션 제목 옆 **+**로 순서 카드를 추가합니다. 새 파일은 **예배 순서 · 자료 편집**에서 불러옵니다.
- 자료 편집에서 섹션 파일/대체 PDF, 섹션 순서, 카드별 제목/음원/소속 섹션을 변경할 수 있습니다. 모든 카드를 옮긴 빈 섹션만 삭제할 수 있습니다.
- 카드가 모두 이동해도 기존 섹션의 자료와 웹 문구 편집은 남습니다. 첫 카드를 옮기거나 삭제해도 다른 카드의 슬라이드가 바뀌지 않습니다.

이전 ‘현재 포함 N개 순서’ 설정은 최초 불러올 때 해당 카드들을 포함하는 PPT 섹션으로 변환합니다. 기존 카드, 음원과 문구 편집을 보존합니다. 같은 파일명으로 별도 섹션이 존재할 수 있으며 각 섹션의 편집은 독립적입니다. 변경은 이 PC에 자동 저장되고 관리자 **서버 저장** 시 카드 배치와 섹션 설정을 함께 저장합니다.

## 좌우 영역 너비 조절

예배 순서 영역과 운영 화면 사이의 세로 경계선을 드래그해 비율을 조절합니다. 비율은 로그인 여부와 관계없이 현재 브라우저에 자동 저장됩니다. 경계선을 더블클릭하면 기본 너비로 돌아옵니다. 키보드로 경계선에 포커스한 뒤 좌우 방향키(Shift는 크게 조절), Home/End(최소/최대), Enter(초기화)를 사용할 수 있습니다. 오른쪽 영역이 좁아지면 미리보기와 버튼을 재배치하고, 600px 이하 화면에서는 위아래 배치를 사용합니다. 화면 2의 출력은 영향을 받지 않습니다.


## 로그인과 관리자 편집

찬양 재생 방식, 자료 편집의 PPT/PDF·MP3 및 섹션, 편집할 슬라이드와 출력 모니터는 버튼으로 선택합니다. 선택된 버튼은 체크와 강조색으로 표시합니다. 방향키·Home·End로도 선택할 수 있으며, 선택 중에는 슬라이드 이동 단축키가 실행되지 않습니다. 긴 파일명은 줄바꿈하고 항목이 많으면 버튼 영역을 스크롤합니다.

예배 이름과 날짜는 상단 **예배 운영 콘솔** 옆에 표시합니다. 관리자 **서버 파일 목록**은 왼쪽 **아름다운교회 영아부** 홈 버튼 옆 구름 아이콘으로 열 수 있습니다. **서버 저장**, **서버 자료 다시 불러오기**, **로그아웃**은 사이드바 아래에 작은 버튼으로 배치되어 있습니다. 출력창 열기는 상단에서 실행하며, 모니터 선택은 상단 연결 상태 영역에서 사용할 수 있습니다.

첫 접속과 비로그인 상태에서는 로그인 화면을 표시합니다. `/admin`, `/worship`, `/output` 직접 접속도 서버에서 세션을 확인하며, 비로그인 자료 조회 API는 401을 반환합니다. 로그아웃하면 로그인 화면으로 돌아가며 다른 열린 탭에도 반영됩니다. 새 문서에서는 온라인으로 세션을 확인하기 전까지 로컬 자료도 표시하지 않습니다. 로그인한 화면이 열린 상태에서는 다운로드한 자료로 오프라인 예배를 계속할 수 있습니다. 미저장 편집본은 별도로 보관하고 **미저장 편집본 복구**를 눌렀을 때만 표시합니다.

카드에는 예배 순서 이름을 크게, 연결된 PPT/PDF·MP3 파일 이름을 작은 회색 글씨로 표시합니다. 왼쪽 **편집 모드 → 카드의 연필 버튼 → 이름 적용**으로 파일 이름과 별개의 순서 이름을 지정할 수 있습니다. **서버 저장** 후 다른 로그인 기기에도 반영되며, 원본 파일 이름과 파일 연결은 유지됩니다. 카드 옆 휴지통으로 삭제할 수도 있습니다. 카드가 없는 PPT 섹션에도 삭제 버튼이 나타납니다. 삭제 전 확인창을 표시하며, 카드 삭제는 섹션의 PPT·문구 편집과 원본 파일을 유지합니다. 빈 섹션 삭제는 그 섹션의 문구 편집을 제거하지만 원본 PPT·MP3 파일은 유지합니다. 변경은 관리자 PC에 자동 저장되며 **서버 저장**을 눌러야 다른 로그인 기기에 반영됩니다.

서버에 저장한 PPT 문구·복사/삭제·순서 메타데이터는 운영 미리보기와 화면 2에도 적용됩니다. 화면으로 돌아올 때, 온라인 복구 시와 표시 중 15초 간격으로 서버 저장본을 확인합니다. 편집 중이거나 편집창이 열려 있으면 자동 갱신을 멈춥니다. **서버 자료 다시 불러오기**로 최신 저장본을 즉시 불러올 수도 있습니다. PC에만 적용하고 서버 저장하지 않은 편집본은 다른 기기에 공유하지 않습니다.


## 서버 저장본과 미저장 편집본

온라인 접속 시 관리자도 최신 서버 저장본으로 시작합니다. PC의 이전 관리자 저장본이 남아 있어도 자동으로 표시하지 않습니다. 서버 연결이 끊겼을 때만 마지막 서버 저장본을 조회용으로 사용합니다.

관리자가 수정하면 **미저장 편집 중**으로 표시하고 변경 내용을 PC에 별도 보관합니다. 새로고침하거나 다시 로그인하면 서버 저장본을 표시하고 **미저장 편집본 복구**를 제공합니다. 복구한 자료는 서버 저장 전까지 관리자에게만 보이며, 이전 서버 버전을 바탕으로 한 편집본은 기존 저장 충돌 검사를 유지해 최신 서버 내용을 덮어쓰지 않습니다. 서버 저장이 완료되면 복구용 편집본을 정리하고 모두 같은 저장본을 사용합니다. 서버 없이 실행하는 로컬 체험 모드는 기존 PC 저장 방식을 유지합니다.
